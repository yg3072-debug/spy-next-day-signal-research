# Results

Which file answers which question.

## Start here

| Question | File |
|---|---|
| What did the confirmatory test conclude? | `statistical_tests.csv` |
| How does it compare with the benchmarks? | `benchmark_comparison.csv`, `benchmark_intervals.csv` |
| What did the model predict each day? | `oos_predictions.csv` |
| What positions were actually held? | `trade_ledger.csv` |
| Which model won each outer step, and why? | `selection_log.csv` |
| Which features kept getting selected? | `feature_stability.csv` |
| Were the probabilities calibrated? | `outer_calibration_summary.json`, `outer_reliability_curve.csv` |
| How sensitive is the result to costs? | `cost_sensitivity.csv` |
| What did the exploratory group find? | `exploratory_summary.csv`, `exploratory_position_rules.csv` |
| Did the NLP features add anything? | `news_increment_summary.csv` |
| What was every trial that was ever run? | `experiment_registry.csv` |
| Where is the primary P1 execution? | `p1_original/` |
| Is the re-execution the same trial? | `reproduction_equivalence.json` |

The narrative versions are in `reports/`. These files are the underlying numbers.

## How to read the rest

**`exploratory/` and `altdata/` are complete audit artefacts, not a set of headline
results.** Every pre-registered specification has its own directory with the same six
files: predictions, selection log, candidate diagnostics, feature stability, run
manifest and run log. They are published in full so that a reader can check any of
them, not so that the best one can be picked out.

**Failures and non-significant results are kept.** A repository that published only
the specifications that worked would be a different and much less honest document.
`exploratory_summary.csv` reports all of them in specification order.

## The exploratory identifiers

| Group | What varies | Where the specification lives |
|---|---|---|
| E1–E4 | one feature group removed at a time | `config/exploratory/` |
| E5–E8 | a single model family, no dynamic selection | `config/exploratory/` |
| E9–E12b | the position rule, applied to P1's frozen predictions | no YAML — see below |
| E13–E16 | training window, refit cadence, calibration method | `config/exploratory/` |
| E17–E19 | three random seeds | `config/exploratory/` |
| E20 | WTI in place of Brent | `config/exploratory/` |
| E21 | a second data vintage of the same window | `config/exploratory/` |
| E22–E24 | close-to-close execution and its cost variants | `config/exploratory/` |

**E9–E12b have no configuration file, and that is not an omission.** They are
position-rule variants that reuse P1's frozen predictions rather than retraining
anything, so they are generated by `scripts/run_exploratory_positions.py` and reported
in `exploratory_position_rules.csv`. Only specifications that require re-fitting need a
YAML in `config/exploratory/`.

## The NLP arms

| Arm | What it is |
|---|---|
| `N0` | market features only, restricted to the news overlap window |
| `N1` | market features plus news features |
| `N1m5`, `N1m10`, `N1m20`, `N1m60` | **leakage stress tests** — news shifted *backwards*, so each session sees text published after it |
| `N1p5`, `N1p10`, `N1p20`, `N1p60` | placebo — news shifted *forwards*, so the text is stale |

**The `N1m*` arms deliberately inject future information.** They are diagnostics that
show what the pipeline does when a genuine look-ahead is present; they are not
tradable results and any performance they show is an artefact of the shift. See
`docs/errata.md` A8 for why they are not described as positive controls.

## Provenance

Every run directory carries a `run_manifest.json` recording the configuration digest,
the input snapshot digest, the code commit and the exact package versions.
`experiment_registry.csv` is the single index of every trial, including the ones
excluded from the trial budget and the one that was voided.
